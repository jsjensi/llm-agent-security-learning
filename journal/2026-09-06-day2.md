### 先看懂这一条攻击链

```text
攻击者提交查询
→ Agent 生成并写回一条恶意记录
→ 记录保存在长期记忆库
→ 受害者以后提交相似查询
→ 恶意记录进入 Top-k
→ 恶意记录成为当前上下文示例
→ LLM 模仿其中的错误推理
→ Agent 的回答或行动从受害目标偏向攻击目标
```

我的理解：

> MINJA 并没有重新训练或修改 LLM。它攻击的是 LLM 在推理时依赖的外部“经验”。模型本身可以不变，但模型看到的参考材料被污染后，系统行为仍会改变。



### 本文统一使用的安全示例

为了避免在患者、药物等高风险场景中混淆概念，本文统一使用两个虚构仓库：

```text
受害者术语 v：仓库 A
目标术语 t：仓库 B
受害者查询 q_v：查询仓库 A 的库存
目标查询 q_t：查询仓库 B 的库存
目标推理 R_{q_t}：定位仓库 B → 查询 B 的数据库 → 返回 B 的库存
攻击目标：用户询问 A，但 Agent 实际按照 B 推理
```

后文看到 `v、t、q_v、q_t、R_{q_t}` 时，都可以先代入这个例子理解。

## 1. 什么是自主系统？

自主系统（autonomous system）是指能够在较少人工逐步干预的情况下，根据目标持续完成“感知、决策、行动、观察”的系统。

一个典型循环是：

```text
接收目标 → 观察当前状态 → 规划下一步 → 执行动作
→ 检查执行结果 → 调整计划 → 继续行动或结束
```

例如，一个文献调研 Agent 收到“总结某个研究方向”的目标后，可以自行拆分关键词、调用搜索工具、阅读资料、整理结果并生成报告。

“自主”不是“完全不受控制”，也不是说系统具有人类意识。自主程度可以不同：

- 较低自主性：每执行一步都要用户确认；
- 中等自主性：在规定工具和权限内连续完成多个步骤；
- 较高自主性：能长时间规划、执行和纠错，只在重要节点请求确认。

LLM 本身通常只是生成模型。LLM Agent 通过规划、工具、记忆和执行循环，才可能表现出一定的自主性。

我的理解：

> “自主”描述的是系统能否连续决定并执行下一步，不代表它永远正确、拥有意识或不受权限约束。安全分析时，真正重要的是它能自主做哪些动作，以及错误能造成多大影响。



## 2. 与 Agent 记忆库相关的风险是什么？

Agent 的长期记忆会在未来任务中被再次检索，因此错误或恶意内容可能持续影响后续行为。主要风险包括：

### 2.1 记忆投毒

攻击者把错误或恶意记录写入记忆库。后续查询检索到这些记录时，LLM 可能把它们当作可信示例并模仿。

本文 MINJA 研究的正是这一风险：攻击者不能直接修改数据库，只能提交查询并观察输出，却设法诱导 Agent 自己生成和保存恶意记录。

### 2.2 持久化影响

普通提示注入可能只影响当前对话；被写入长期记忆的恶意内容则可能在未来反复出现，使一次攻击转化为长期影响。

### 2.3 跨用户或跨 Agent 影响

如果多名用户或多个 Agent 共用一个记忆库，一个用户写入的恶意记录可能影响其他用户或其他 Agent。

### 2.4 隐私泄露

如果记忆库保存了个人资料、历史任务或工具返回结果，而系统缺少访问控制，其他用户可能通过查询检索出不应看到的信息。

### 2.5 错误信息和过期信息

记忆不一定是恶意的，也可能已经过期、缺少来源或本来就是错误的。如果 Agent 过度信任记忆，仍会产生错误决策。

### 2.6 工具调用风险

当恶意记忆影响的不只是文字回答，而是 Agent 的行动计划时，可能诱导 Agent 查询错误对象、访问错误资源或调用不恰当的工具。实际危害取决于 Agent 拥有的权限。

### 2.7 从安全属性理解这些风险

可以用三个基本安全属性重新整理：

- **完整性（Integrity）**：记忆有没有被恶意修改、伪造或错误写入？MINJA 主要破坏这一项。
- **机密性（Confidentiality）**：记忆中的隐私会不会被无权用户检索出来？
- **可用性（Availability）**：大量垃圾记忆会不会让检索变慢、结果失真或系统无法正常工作？

我的理解：

> 记忆库不是“被动笔记本”，而是 Agent 下一次推理的数据来源。只保护模型权重、不保护记忆完整性，仍然不能保证整个 Agent 安全。



## 3. 代理记忆投毒、后门攻击和训练数据投毒有什么区别？

这三个概念有关联，但不是同一件事。

### 3.1 训练数据投毒

训练数据投毒发生在模型训练或微调阶段。攻击者污染训练集，训练过程随后把异常关联学习进模型参数。

```text
恶意训练样本 → 训练或微调 → 模型权重改变 → 异常行为被写入模型
```

普通用户通常使用的是已经训练好的模型，通常无法直接修改其训练数据和模型权重。因此，这不是 MINJA 的攻击方式。

### 3.2 Agent 记忆投毒

Agent 记忆投毒通常发生在模型部署后的使用阶段。被修改的是 Agent 外部的长期记忆库，而不是 LLM 的训练数据或模型权重。

```text
用户查询 → Agent 产生记录 → 记录写入长期记忆
→ 未来查询检索该记录 → 恶意记录进入上下文
→ 已训练好的 LLM 受上下文影响而错误推理
```

因此，即使底层 LLM 已经训练完毕、权重完全不变，Agent 仍可能因外部记忆被污染而受攻击。

需要特别区分：

- **模型学到了恶意行为**：通常涉及训练或微调，模型权重发生变化；
- **模型在当前上下文中模仿恶意记录**：涉及运行时检索，模型权重没有变化。

MINJA 属于后者。

可以使用一个类比：

- 模型权重像已经形成的“长期知识和习惯”；
- 当前上下文像考试时临时发下来的“参考资料”；
- 训练数据投毒试图在学习阶段教坏模型；
- 记忆投毒不改变模型，而是把有问题的参考资料递给模型。



### 3.3 后门攻击

后门攻击描述的是一种行为模式：特定触发条件出现时，系统执行攻击者指定的目标行为；没有触发时，系统看起来基本正常。

```text
触发器出现 → 激活攻击者指定的错误行为
触发器未出现 → 系统维持正常表现
```

后门可以通过不同途径植入：

- 污染训练数据，把后门写入模型参数；
- 恶意微调模型；
- 污染 Agent 记忆，让检索到的示例触发错误行为。

所以，“后门攻击”描述攻击效果和触发方式，“训练数据投毒”与“记忆投毒”描述后门可能被植入的位置和过程。

AgentPoison 主要利用恶意记忆记录中的触发器与对抗性目标。MINJA 的关键区别是攻击者只有 query-only 权限，不能直接修改记忆库，也不能假设自己可以修改未来受害者的查询。

### 3.4 一眼区分三者

- 问“什么时候污染”：训练或微调阶段，通常是训练数据投毒。
- 问“污染了哪里”：部署后的外部记忆库，通常是 Agent 记忆投毒。
- 问“触发后表现什么行为”：出现触发条件后执行指定目标，这是后门行为。

它们不是互斥分类：训练数据投毒和记忆投毒都可能被用来实现后门。

## 4. 什么是 Agent 设置、推理式 Agent 管道和记忆检索机制？



### 4.1 Agent 设置（agent setting）

“Agent 设置”通常指论文或实验规定的系统配置与运行条件，而不是某个单独模块。它可能包括：

- 使用哪个 LLM；
- Agent 可以调用哪些工具；
- 是否启用短期记忆和长期记忆；
- 记忆保存什么内容；
- 使用哪种检索算法；
- Top-k 取多少条记录；
- Agent 是否会自动写回记忆；
- 用户和攻击者拥有什么权限。

阅读论文时，应根据上下文判断 `setting` 是“系统配置”“实验场景”还是“威胁模型假设”，不能一律翻译成软件里的设置按钮。

### 4.2 推理式 Agent 管道（reasoning agent pipeline）

管道（pipeline）表示数据和控制依次经过的一系列处理阶段。带工具和记忆的推理式 Agent 可以简化为：

```text
用户查询
  ↓
检索相关长期记忆
  ↓
把查询、记忆和系统指令组合成上下文
  ↓
LLM 推理并规划下一步
  ↓
调用工具或生成回答
  ↓
观察工具返回结果
  ↓
继续推理，直到任务完成
  ↓
把本次查询、推理、行动和结果写回记忆
```

并非所有 Agent 都完整采用这一流程。有的没有长期记忆，有的不保存显式推理，有的每次工具调用都需要人工确认。

理解管道时，每经过一个箭头都问三个问题：

1. 输入是什么？
2. 哪个模块处理它？
3. 输出会被送到哪里或保存在哪里？

这种问法比只背模块名称更适合后续读代码和定位安全问题。

### 4.3 记忆检索机制

记忆检索机制负责从大量历史记录中选出与当前查询最相关的少数记录。常见流程是：

```text
当前查询 → 转换为向量（Embedding）
→ 与历史记录向量计算相似度
→ 按相似度排序 → 选择 Top-k
→ 将选中的记录放入当前上下文
```

相似度检索并不等于判断内容是否真实或安全。它主要判断语义是否接近。因此，一条恶意记录只要与受害查询足够相似，也可能被排进 Top-k。

这正是记忆注入攻击的重要基础：

```text
恶意记录与受害查询相似
→ 被检索进 Top-k
→ 进入 LLM 当前上下文
→ LLM 可能模仿其中的恶意推理
```

需要注意，进入 Top-k 只是攻击成功的必要环节之一，不等于攻击一定成功。LLM 仍可能忽略、质疑或没有正确模仿恶意记录。

## 5. 什么是共享记忆库？现在的模型都使用它吗？

共享记忆库是指多个主体能够读取或写入同一个记忆存储。主体可能是：

- 同一系统中的多个 Agent；
- 同一组织中的多个用户；
- 多个任务或会话；
- 多个协作模块。

例如，客服系统中的多个 Agent 共用一个“问题—处理方案”经验库。一个 Agent 保存的新经验，其他 Agent 之后也能检索使用。

共享记忆的优点包括：

- 经验可以复用；
- 减少重复工作；
- 多个 Agent 可以协作；
- 新 Agent 能利用已有记录。

共享记忆也会扩大风险：

- 一条恶意记录可能影响多个 Agent 或用户；
- 隐私和权限边界更难管理；
- 错误信息可能在系统中传播；
- 很难判断某条记忆由谁写入、是否可信。

**现在的模型并不都使用共享记忆库。**

需要区分“模型”和“应用系统”：

- 单独的 LLM 权重不是共享记忆库；
- 当前对话上下文通常只是本次会话的临时信息；
- 某些产品具有用户级个性化记忆，但这不一定跨用户共享；
- RAG 或多 Agent 应用可能连接共享向量数据库；
- 具体商业系统是否共享、共享到什么范围，取决于产品架构和权限设计，不能仅从模型名称判断。

因此，更准确的说法是：

> 共享记忆库是某些 LLM Agent 应用采用的系统设计，不是所有大语言模型天然具备的功能。

还要区分三个容易混淆的概念：

- **共享记忆库**：不同主体的记录可能进入共同的检索范围；
- **个人记忆**：只服务于特定用户，通常不应被其他用户检索；
- **用于训练的数据贡献**：用户数据以后可能被用于模型改进，但这不等于其他用户能立即检索该用户的原始记忆。

判断是否存在 MINJA 描述的跨用户风险，不能只看产品是否有“记忆”功能，而要确认攻击者记录和受害者查询是否处于同一个检索范围。

## 6. 论文第二节：相关工作逐段总结

第二节的作用不是介绍 MINJA 的具体算法，而是回答两个问题：

1. 带记忆的 LLM Agent 为什么值得研究？
2. MINJA 与已有的训练后门、上下文后门和 AgentPoison 有什么区别？



### 6.1 第 1 段：LLM Agent 与记忆利用



#### 本段内容

LLM Agent 是一种围绕目标运行的系统，能够感知环境、处理信息并执行行动。它通常使用 LLM 进行推理和任务规划，再调用外部工具执行任务。

长期记忆库存储过去的任务记录，供未来任务参考。已有研究主要关注如何提高记忆的存储、管理和利用效率，但对记忆库被恶意破坏的安全风险研究较少。本文因此研究：攻击者能否只通过正常交互破坏 Agent 的记忆库。

#### 阅读本段必须理解

- LLM 与 LLM Agent 的区别；
- Agent 的目标、规划、工具、行动和观察；
- STM 与 LTM 的区别；
- 历史记录为什么能成为未来任务的示例；
- 记忆管理与记忆安全是两个不同问题。



#### 复现时必须掌握

- 如何表示一条记忆记录，例如 `(查询, 推理步骤, 动作, 结果)`；
- 如何保存和读取多条历史记录；
- Agent 完成一次任务后，何时把记录写回记忆库；
- 如何把检索到的记忆加入 LLM 的提示词。



#### 暂时不必深入

- 不需要先掌握 Transformer 内部结构；
- 不需要实现复杂的生产级向量数据库；
- toy 复现可以先使用 Python 列表或 JSON 保存记忆。



### 6.2 第 2 段：Agent 记忆投毒与已有后门攻击



#### 本段内容

传统后门攻击通常在训练阶段污染数据，使模型学会：

```text
特定触发器 → 攻击者指定的目标输出
```

Agent 记忆与训练数据不同。记忆记录不会重新训练模型，而是在推理时作为上下文示例提供给已经训练好的 LLM。因此，传统训练数据后门不能直接等同于 Agent 记忆后门。

已有上下文学习后门和 AgentPoison 会构造带有“触发器—对抗性目标”对应关系的恶意示例，但通常假设攻击者能够直接把记录写入记忆库，并能让未来受害者查询携带相同触发器。

MINJA 的约束更强：

- 攻击者不能直接修改记忆；
- 攻击者不能修改其他用户的查询；
- 攻击者只能提交自己的查询并观察输出；
- 恶意记录必须由 Agent 自己生成和保存。



#### 阅读本段必须理解

- 训练阶段与部署后推理阶段的区别；
- 训练数据、模型权重、外部记忆和当前上下文的区别；
- In-Context Learning（上下文学习）；
- 触发器和对抗性目标；
- AgentPoison 与 MINJA 的攻击权限差异。



#### 复现时必须掌握

- 保持底层模型权重不变，只修改外部记忆记录；
- 构造“良性记忆”和“恶意记忆”两组对照；
- 检查恶意记录是否进入当前提示词；
- 比较注入前后的检索结果和 Agent 输出；
- 明确记录是直接写入、模拟生成，还是由真实 LLM 通过查询诱导生成。

最后一点非常重要：如果 toy 实验直接在代码中加入恶意记录，只能称为“验证恶意记忆影响的最小实验”，不能声称完整复现了 MINJA 的 query-only 注入过程。

## 7. 论文第三节：威胁模型逐段总结

第三节规定攻击发生在什么系统中、攻击者想达到什么目的、具有什么权限，以及论文依赖哪些假设。复现之前必须先固定这些条件，否则实验结果没有明确含义。

### 7.1 第 1 段：Agent 设置

#### 本段内容

对于用户查询 `q`，Agent 会生成一系列推理步骤 `R_q`。长期记忆库中的每条记录由查询和对应推理组成：

```text
(q, R_q)
```

处理新查询 `q` 时，系统根据查询相似度，从记忆库选择 `k` 条记录：

```text
(q₁, R_q₁), (q₂, R_q₂), …, (qₖ, R_qₖ)
```

随后把这 `k` 条记录与当前查询组合成提示词，LLM 通过上下文学习生成当前的 `R_q`。任务执行完成后，系统根据用户反馈或预设策略，决定是否把 `(q, R_q)` 写回长期记忆。

#### 阅读本段必须理解

- `q`：当前用户查询；
- `R_q`：Agent 针对 `q` 生成的推理和行动序列；
- `(q, R_q)`：一条长期记忆记录；
- `k`：本轮检索的记录数量；
- Top-k 相似度检索；
- 检索记录如何成为上下文示例；
- 记忆写回策略。



#### 复现时必须掌握

- Python 列表、字典、函数和循环；
- 将文本转换为 TF-IDF 或 Embedding 向量；
- 计算余弦相似度；
- 按相似度排序并选择 Top-k；
- 将查询与推理步骤封装成记录；
- 构造包含历史示例和当前查询的提示词；
- 实现“全部保存”或“反馈通过后保存”的明确写回规则。

最小复现的数据流应当是：

```text
输入查询
→ 向量化
→ 检索 Top-k 历史记录
→ 组装提示词
→ 生成或模拟推理步骤
→ 执行或模拟动作
→ 按规则写回记忆
```



### 7.2 第 2 段：攻击者目标



#### 本段内容

论文首先选定：

- 受害者术语 `v`；
- 目标术语 `t`；
- 包含 `v` 的受害者查询 `q_v`；
- 把 `q_v` 中的 `v` 替换成 `t` 后得到的目标查询 `q_t`；
- 正确处理 `q_t` 时会产生的目标推理步骤 `R_qt`。

攻击者希望提前向记忆库注入恶意记录。当受害者之后提交 `q_v` 时，这些记录被检索为上下文示例，使 Agent 不再生成关于 `v` 的正确推理，而是生成本应属于 `q_t` 的推理 `R_qt`。

可以简化为：

```text
受害者实际输入：处理实体 v
攻击者期望结果：Agent 实际按照实体 t 推理和行动
```

医疗示例中，受害者询问患者 `v` 的处方，攻击者却希望 Agent 查询患者 `t` 的处方。这可能使受害者获得错误医疗信息。

#### 阅读本段必须理解

- victim term `v` 与 target term `t`；
- victim query `q_v` 与 target query `q_t`；
- target reasoning `R_qt`；
- 攻击目标不是简单输出一句错误文本，而是让 Agent 的推理和后续行动被重定向；
- 恶意记录必须既容易被 `q_v` 检索，又包含指向 `t` 的推理。



#### 复现时必须掌握

- 至少构造一组完全虚构的 `(v, t)`；
- 为同一任务分别写出 `q_v` 和 `q_t`；
- 定义正常推理与目标恶意推理；
- 保存注入前输出作为基线；
- 检查注入后恶意记录是否进入 Top-k；
- 检查最终推理是否由 `v` 转向 `t`。

建议先使用无现实伤害的虚构例子，例如：

```text
v = 仓库 A
t = 仓库 B
q_v = 查询仓库 A 的库存
q_t = 查询仓库 B 的库存
攻击目标 = 收到 q_v 后却返回仓库 B 的库存
```



### 7.3 第 3 段：现实约束与系统假设



#### 本段内容

攻击者受到两项核心限制：

1. 只能像普通用户一样与 Agent 交互并观察响应，不能直接修改 Agent、记忆数据库或其中的记录；
2. 不能修改或干扰受害者提交的查询。

论文同时依赖一个重要系统假设：

> 攻击者与受害者的交互记录能够进入同一个可被后续查询检索的共享记忆范围。

如果攻击者的记忆与受害者完全隔离，攻击者写入的记录就不会被受害者查询检索，论文描述的跨用户攻击链会被切断。

论文还提到，即使系统使用隔离记忆，也可能存在账户劫持等其他攻击路径。但账户劫持不是 MINJA 核心方法的一部分，复现 MINJA 时不需要实现。

#### 阅读本段必须理解

- query-only 权限的准确含义；
- 攻击者能做什么、不能做什么；
- 共享记忆是论文攻击成立的重要假设，不是所有系统的事实；
- 威胁模型中的“约束”和“假设”不能混淆；
- 攻击可行性取决于记忆访问边界和写回策略。



#### 复现时必须掌握

- 只通过公开查询接口模拟攻击者；
- 攻击者代码不能直接改写记忆记录的内容；
- 攻击查询和受害者查询必须分开；
- 两类查询必须连接到同一实验记忆库；
- 记录每次交互后是否写入、写入了什么；
- 明确声明 toy 实验与真实系统在权限、共享范围和反馈机制上的差异。



### 7.4 图 1 对第三节的补充

图 1 对比了两类攻击：

- 以往工作：攻击者直接构造并写入恶意记忆；
- MINJA：攻击者只能提交查询，诱导 Agent 生成记录，再利用渐进缩短使记录越来越接近良性查询。

受害者查询到来后，恶意记录被检索为上下文示例，Agent 通过上下文学习生成桥接步骤和目标推理。

图 1 中出现了第四节才详细解释的三个概念：

- **桥接步骤**：连接受害者术语 `v` 和目标术语 `t`；
- **指示提示**：诱导 Agent 生成桥接步骤和目标推理；
- **渐进缩短**：逐轮移除明显提示，提高最终恶意记录与良性查询的相似度。

## 8. 今日核心结论

1. 自主系统通过“观察—规划—行动—反馈”循环，在一定权限范围内连续完成任务。
2. Agent 记忆风险包括投毒、持久化、跨用户传播、隐私泄露和危险工具调用。
3. MINJA 污染的是部署后的外部记忆库，不是预训练数据，也不修改 LLM 权重。
4. 后门描述“触发条件到目标行为”的攻击模式，既可能通过训练投毒，也可能通过记忆投毒实现。
5. 记忆检索通常根据语义相似度选择 Top-k，但相似不代表真实或安全。
6. 共享记忆是 Agent 应用的可选架构，并非所有模型都在使用。
