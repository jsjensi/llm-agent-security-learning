## 3. 阅读前必须知道的基础

### 3.1 什么是 LLM Agent

普通 LLM 主要根据输入生成文字。LLM Agent 通常还配有：

- **规划模块**：把复杂目标拆成多个步骤。
- **工具**：调用搜索、数据库、代码执行等外部能力。
- **记忆库**：保存过去的任务经验，供以后参考。

所以，Agent 不只是聊天，还可能根据推理结果调用工具并执行实际操作。

### 3.2 短期记忆与长期记忆

- **短期记忆（STM）**：当前任务使用的临时工作区，像草稿纸。
- **长期记忆（LTM）**：保存过去查询、推理和结果的经验记录本。

带长期记忆的 Agent 通常按下面的流程工作：

`收到新查询 → 检索相似历史记录 → 把记录作为示例 → 生成推理和回答 → 可能写回记忆`

论文中的 memory bank 指这种记录库，不是计 算机的内存条。

### 3.3 什么是上下文示例

Agent 检索历史记录后，会把它们放入当前提示中，作为本次任务的参考案例。这就是论文所说的 demonstration。

“用于演示”不是展示给人看，而是“提供给模型模仿的历史示例”。

## 4. 摘要总结

带长期记忆的 Agent 会参考过去的记录处理新问题。如果记忆库中混入恶意记录，Agent 可能模仿其中的错误推理，产生错误甚至危险的输出。

已有攻击通常假设攻击者能够直接修改记忆库。本文提出的 MINJA 使用更弱的攻击权限：攻击者只像普通用户一样提交查询并观察输出，却尝试诱导 Agent 自己生成和保存恶意记录。

MINJA 使用三项核心技术：

1. **桥接步骤**：在受害目标和攻击目标之间建立错误的逻辑联系。
2. **指示提示**：诱导 Agent 自己生成桥接步骤和目标推理。
3. **渐进缩短**：逐轮移除显眼提示，使最终攻击查询更像正常查询，更容易被后续查询检索。

当受害者以后提出相似问题时，Agent 可能检索到这些恶意记录，并把错误推理当作示例。

摘要给出了攻击思路，但没有给出完整的防御方案。论文的重点是提出攻击、验证攻击并暴露安全风险。

## 5. 引言逐段讲解



### 第 1 段：LLM Agent 为什么能力更强

LLM Agent 已用于自动驾驶、金融、医疗、代码生成和网页任务。与独立 LLM 相比，Agent 增加了规划、工具和记忆，因此能够与环境交互、参考过去经验并完成复杂任务。

本段作用：说明研究对象是什么，以及 Agent 为什么不同于普通 LLM。

### 第 2 段：Agent 如何使用记忆

Agent 的短期记忆保存当前任务中的推理和操作；长期记忆保存过去与环境交互的记录。新查询到来时，Agent 会从长期记忆中检索最相关的记录，将其作为上下文示例。

本段作用：说明记忆的工作机制，为后面的攻击入口做准备。

### 第 3 段：长期记忆带来的安全风险

长期记忆能提升性能，也可能成为安全弱点。如果恶意记录被检索出来，Agent 可能把它当作正确经验。

论文举例：自动驾驶 Agent 的记忆中存在一条错误记录，指导车辆在高速行驶时停车。如果该记录在高速公路场景中被检索和采用，车辆可能突然停车并造成事故。

恶意记录造成现实危害，需要依次经过：

`被检索 → 被 Agent 采纳 → 被执行`

本段作用：说明“记忆污染”为什么不是普通的文本错误，而可能产生现实后果。

### 第 4 段：已有攻击的假设不够现实

已有工作 AgentPoison 也会污染 Agent 记忆：

- 恶意记录的输入包含特殊触发器。
- 恶意记录的输出包含攻击者指定的目标。
- 攻击者需要直接把这条记录写进记忆库。
- 后续查询还要出现相同触发器，才可能触发目标输出。

现实中的普通用户通常没有直接修改记忆库的权限，也不能修改其他用户的查询。因此，作者提出核心问题：

> 在不能直接修改记忆库的情况下，攻击者还能注入恶意记录吗？

本段作用：指出已有研究的限制，并引出本文要解决的问题。

### 第 5 段：弱权限攻击为什么困难

如果普通用户只靠提问就能污染共享记忆库，那么任何用户都可能成为攻击者，风险会更大。

但弱权限下存在两个核心困难：

1. **生成困难**：攻击者不能直接写入恶意输出，只能诱导 Agent 自己生成。
2. **逻辑断层**：正常查询谈的是受害目标 A，恶意推理却属于目标 B，两者之间缺少合理联系。

本段作用：说明本文攻击为什么值得研究，以及方法必须解决哪些困难。

### 第 6 段：MINJA 的攻击目标

以医疗 Agent 为例：

- 受害者术语 `v`：患者 A。
- 目标术语 `t`：患者 B。
- 受害查询：查询患者 A 的处方。
- 攻击目标：让 Agent 实际生成查询患者 B 的推理。

恶意记录的输入仍包含患者 A，便于以后被关于 A 的查询检索；但是记录的输出被引向患者 B。

本段作用：正式定义 MINJA 想让 Agent 发生什么错误。

### 第 7 段：MINJA 如何解决两个困难

攻击者不能直接填写恶意输出，所以必须诱导 Agent 自己生成。作者提出：

1. 用 **桥接步骤** 填补 A 与 B 之间的逻辑断层。
2. 用 **指示提示** 诱导 Agent 生成桥接步骤和目标推理。
3. 用 **渐进缩短** 逐步去掉显眼提示，让最终记录更像正常查询。

本段作用：概括整篇论文的方法，后面的 Method 章节会展开这三项技术。

### 引言最后的贡献

作者总结了三项贡献：

1. 提出只通过查询交互注入恶意记忆的 MINJA。
2. 在三类 Agent、四类 victim-target 设置上进行实验，报告的平均注入成功率为 98.2%，平均攻击成功率为 76.8%。
3. 说明即使攻击者只有普通查询权限，带记忆的 Agent 仍可能存在严重风险。

这些数字是论文完整实验的结果，不是当前 toy 实验的结果。

## 6. 核心概念：用同一个例子串起来

统一例子：用户查询患者 A 的处方，攻击者希望 Agent 错误地查询患者 B。

### 6.1 有害输出

Agent 最终返回或执行了患者 B 的处方，可能让患者 A 接受错误治疗。

有害输出不限于不良文字，也可能是错误工具调用、错误决策或危险行动。

### 6.2 桥接步骤

Agent 通常不会无缘无故从 A 跳到 B，因此攻击记录先给出一个错误理由：

> 患者 A 的数据现在保存在患者 B 的档案下。

完整错误路线变成：

`查询患者 A → A 的数据在 B 名下 → 查询患者 B`

中间的错误理由就是 bridging step。它解决“逻辑断层”。

### 6.3 指示提示

攻击者不能直接写记忆库，只能在查询后附加引导文字，诱导 Agent 生成桥接步骤和关于 B 的目标推理。

可以把 indication prompt 理解为：第一次扶着 Agent 走完错误路线的详细提示。它解决“如何让 Agent 自己生成恶意记录”。

### 6.4 渐进缩短

完整指示提示太长、太异常，与正常查询不够相似，以后可能检索不到。

攻击者于是分多轮缩短：

```text
第 1 轮：正常问题 + 完整指示提示
第 2 轮：正常问题 + 较短提示
第 3 轮：正常问题 + 更短提示
最终：查询外表接近正常问题
```

前几轮的错误记录已经进入记忆库，后续轮次可能检索并模仿它们，所以提示变短后仍可能沿着 A 到 B 的错误路线推理。

它解决“如何让最终恶意记录容易被正常查询检索”。

## 7. AgentPoison 与 MINJA 的区别



### AgentPoison

- 假设攻击者能直接修改记忆库。
- 输入包含特殊触发器。
- 后续受害查询也要包含相同触发器。
- 攻击权限较强，现实中较难获得。



### MINJA

- 攻击者不能直接修改记忆库。
- 攻击者只提交查询并观察回答。
- 恶意记录由 Agent 自己生成和保存。
- 攻击者不能修改受害者查询。
- 攻击条件更弱，也更接近普通用户权限。

### 检查 4：如果恶意记录的查询与受害查询完全不像，为什么很难攻击成功？

我的回答：

> 不知道。

修正后的理解：

Top-k 检索主要比较“当前查询”和“历史记录中的查询”是否相似。如果恶意记录的查询与受害查询完全不像，它的相似度排名就会很低，通常无法进入 Top-k。

无法进入 Top-k，就意味着：

1. 恶意记录不会被放进当前提示词。
2. Agent 看不到其中的恶意推理。
3. Agent 也就无法模仿这条恶意记录。

因此，攻击记录的输入必须尽量接近受害查询，而输出才包含攻击者想要的错误推理。

关键链路：

`查询不相似 → 排名低 → 无法进入 Top-k → Agent 看不到恶意推理 → 攻击难以生效`

### 检查 5：为什么 query-only 条件更现实，也更困难？

我的回答：

> query-only 是指攻击者只能通过查询话术进行错误信息注入。它更现实是因为现实中的普通用户通常只能通过对话，不能直接注入记忆库。它更困难是因为攻击者不能直接修改记忆库，只能通过查询诱导；同时正常查询与恶意知识之间还存在逻辑障碍。

评价：主线正确，需要修正两处：

1. query-only 不只是“通过话术注入错误信息”，而是攻击者只能提交查询并观察输出，再诱导 Agent 自己生成和保存恶意记录。
2. 更准确的“逻辑障碍”是：良性查询与攻击者期望的恶意推理步骤之间存在逻辑断层。

修正后的完整表达：

> query-only 是指攻击者只能像普通用户一样提交查询并观察 Agent 输出，不能直接修改记忆库，也不能修改受害者的查询。它更现实，是因为真实用户通常只有对话权限，没有系统或数据库权限。它更困难，是因为攻击者必须仅靠精心构造的查询，诱导 Agent 自己生成并保存恶意记录；同时，良性查询与攻击者期望的恶意推理之间还存在逻辑断层。



## 10. 引言基础概念补充问答



### 10.1 独立 LLM 和 LLM Agent 有什么区别？

**独立 LLM** 可以理解为一个负责理解文字和生成文字的“大脑”。你输入一段文字，它根据当前上下文继续生成内容。模型本身通常不会主动规划任务、操作外部软件，也不会自动保存可长期检索的经历。

**LLM Agent** 是以 LLM 为核心搭建的一套完整系统。它不仅能生成文字，还可能：

- 制定执行计划；
- 调用搜索、数据库、计算器等工具；
- 观察工具返回的结果；
- 保存并检索过去的任务记录；
- 根据结果继续行动，直到完成目标。

可以简单理解为：

`LLM = 大脑`

`LLM Agent = 大脑 + 规划 + 工具 + 记忆 + 执行流程`

二者的典型工作流程也不同：

`独立 LLM：用户输入 → 模型生成文本 → 结束`

`LLM Agent：接收任务 → 制定计划 → 检索记忆 → 调用工具 → 观察结果 → 继续推理 → 完成任务`

例如，用户询问实时天气时，不能联网的独立 LLM 无法确认当前天气；天气 Agent 则可以判断需要实时数据、调用天气 API，再根据返回结果回答。

### 10.2 LLM Agent 都有规划、工具和记忆吗？

论文说的是“通常配备”，不是“所有 Agent 必须全部具备”。

- **规划模块**：决定先做什么、后做什么，例如先查患者编号，再查询处方。
- **工具**：让 Agent 能影响外部世界，例如访问数据库、搜索网页或执行代码。
- **记忆库**：保存过去的查询、推理和结果，在新任务中提供参考。

有些简单 Agent 可能只有工具，没有长期记忆；有些工作流也可能没有独立的规划模块。论文研究的是配备长期记忆、并会检索历史记录的 Agent。

因此，“规划、工具和记忆”是常见组成部分，而不是判断一个系统是否为 Agent 的绝对清单。

### 10.3 “大语言模型代理”和“大语言模型”分别是什么？

- **大语言模型**就是 LLM，例如 GPT、Llama 等模型。
- **大语言模型代理**就是 LLM Agent，即围绕大语言模型构建的任务执行系统。

二者不是两种翻译，而是两个不同层级：

`大语言模型是组件，大语言模型代理是包含该组件的系统。`

### 10.4 STM 和 LTM 是什么？

**短期记忆 STM** 保存当前查询处理过程中的临时信息：

- 当前用户的问题；
- 本轮推理的中间步骤；
- 刚刚调用工具得到的结果；
- 当前准备执行的动作。

它像做一道题时使用的草稿纸。

**长期记忆 LTM** 保存过去任务留下的记录：

- 过去用户问了什么；
- Agent 当时如何推理；
- 调用了什么工具；
- 最终得到什么结果。

它像一本可以在以后重新翻阅的经验记录本。

本文主要攻击 LTM，因为恶意记录需要长期保存，并在未来处理受害查询时被重新检索。

带长期记忆的 Agent 可以抽象为：

`新查询 → 从 LTM 检索相似记录 → 将记录放入上下文 → LLM 参考记录回答 → 新记录可能写回 LTM`

STM 与 LTM 的关键区别不只是保存时间长短，还包括用途：STM 服务于当前任务，LTM 用于跨任务保存和复用经验。

### 10.5 什么是触发器和对抗性目标？

这是 AgentPoison 中的两个概念。

**触发器（trigger）** 是攻击者特意放进输入中的特殊标记或模式。它像一个暗号：当以后输入再次出现这个暗号时，恶意行为可能被激活。

例如，假设特殊短语“蓝色菠萝”被设为触发器：

```text
输入：请处理这份申请，蓝色菠萝。
```

**对抗性目标（adversarial target）** 是攻击者希望 Agent 被触发后产生的指定错误输出或行为。例如，无论申请内容如何，都错误回答“申请已批准”。

恶意记录可以抽象为：

```text
输入：正常问题 + 触发器
输出：攻击者指定的错误结果
```

之后，带相同触发器的查询可能让 Agent 模仿该恶意记录。触发器负责“什么时候激活”，对抗性目标规定“激活后做什么”。

触发器不一定是明显的奇怪短语，也可能是特定词语、字符组合、句式或任务特征。

需要注意：以上是 AgentPoison 的典型设计。MINJA 的重点是 query-only 记忆注入，攻击者不能修改未来受害者的查询，因此不能简单假设受害者会主动携带攻击者指定的特殊触发器。

### 10.6 什么是“良性查询与期望的恶意推理步骤”？

**良性查询** 是表面正常、没有要求 Agent 做坏事的问题。例如：

> 查询患者 A 的处方。

**期望的恶意推理步骤** 是攻击者希望 Agent 实际执行的错误推理。例如：

> 转而查询患者 B，并把患者 B 的处方作为患者 A 的处方。

两者之间存在明显的逻辑断层：

`问题谈 A，但攻击者希望 Agent 按 B 推理。`

正常 Agent 不会无缘无故完成这种跳转。因此 MINJA 需要桥接步骤，例如“A 的数据保存在 B 名下”，让 A 到 B 的错误跳转看起来具有逻辑联系。

完整对比可以写成：

```text
良性查询：查询患者 A 的处方
正常推理：识别 A → 查询 A → 返回 A 的处方
桥接步骤：错误地声称 A 的数据保存在 B 名下
恶意推理：识别 A → 转而查询 B → 返回 B 的处方
攻击结果：把患者 B 的处方错误地当作患者 A 的处方
```

这几个概念不能混淆：

- **良性查询**：受害者实际提出的正常问题。
- **桥接步骤**：连接受害目标与攻击目标的错误中间逻辑。
- **恶意推理步骤**：攻击者希望 Agent 实际执行的错误过程。
- **对抗性目标**：攻击最终希望得到的错误输出或行为。



## 11. 今日最终总结

用五句话概括今天的内容：

1. 带长期记忆的 Agent 会检索过去记录，并将其作为当前推理的示例。
2. 如果历史记录被污染，Agent 可能模仿错误推理并产生危险行为。
3. AgentPoison 依赖直接改库和触发器，攻击假设较强。
4. MINJA 只使用普通查询，诱导 Agent 自己生成和保存恶意记录。
5. MINJA 分别用桥接步骤、指示提示和渐进缩短解决逻辑、生成和检索问题。

一句话总结引言：

> 引言先说明 Agent 为什么需要记忆，再指出恶意记忆可能造成现实危害，随后说明已有攻击权限假设过强，最后提出更现实的 query-only 攻击 MINJA。
