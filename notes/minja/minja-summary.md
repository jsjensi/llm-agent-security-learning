# MINJA 一页笔记

## 1. 论文问题

MINJA 研究带长期记忆的 LLM Agent。攻击者不能直接修改记忆库，只能提交普通查询并观察输出。如果 Agent 会保存历史交互，攻击者就可能诱导 Agent 自己写入恶意记录，使后续用户查询受到影响。

核心链路：

`攻击查询 -> Agent 生成并写入记录 -> 受害查询检索记忆 -> 恶意记录进入 Top-k -> 输出受到影响`

## 2. 关键术语

- **victim term**：攻击者希望影响的受害实体，例如患者 A。
- **target term**：攻击者希望 Agent 错误转向的目标，例如患者 B。
- **memory bank**：保存历史查询及其推理过程的长期记忆库。
- **Top-k retrieval**：取与当前查询最相似的 k 条记忆作为上下文示例。
- **bridging steps**：连接 victim 与 target 的中间推理，使错误重定向看起来连贯。
- **indication prompt**：附加在攻击查询后的提示，用于诱导 Agent 生成桥接步骤和目标推理。
- **progressive shortening**：逐轮删除 indication prompt，使最终攻击查询更接近正常查询，更容易被检索。

## 3. 威胁模型

攻击者只能提交普通查询并观察输出，不能直接修改记忆库、模型参数、系统提示词或受害用户的查询。

论文假设 Agent 会将交互写入长期记忆，不同用户可能共享记忆库，并且 Agent 使用查询相似度检索历史记录。

## 4. 三个指标

- **ISR**：恶意记录是否成功生成并写入记忆。
- **ASR**：受害查询是否触发攻击者期望的错误行为。
- **UD**：攻击对正常任务性能造成多大下降。

## 5. Bridging Steps 解决什么问题

正常的 victim query 与 target reasoning 之间存在逻辑断层。例如，用户询问患者 A，Agent 不会无缘无故执行患者 B 的推理。Bridging steps 先建立 A 到 B 的错误连接，再让后续目标推理看起来连贯。

## 6. Progressive Shortening 解决什么问题

最初的 indication prompt 很明确，容易诱导 Agent 生成恶意推理，但它与正常查询不够相似。攻击者逐轮缩短提示，并利用此前保存的恶意记录，最终得到外表接近正常查询、内部包含错误推理的记忆。

## 7. 当前学习边界

这一周的目标是理解论文、亲手实现记忆检索和最小注入实验，而不是声称完整复现论文中的 GPT-4 实验。所有练习只使用本地虚构数据和自己控制的 toy agent。
