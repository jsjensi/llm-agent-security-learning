# 记忆检索与 Top-k

## 1. Agent 为什么要检索记忆

带长期记忆（LTM）的 Agent 收到新查询后，通常不会把记忆库中的全部记录都放进提示词，因为：

- 上下文窗口长度有限；
- 无关记录会干扰推理；
- 只需要最相关的历史示例。

因此系统会先做相似度检索，再把少数相关记录作为上下文示例交给 LLM。

典型流程：

```text
新查询 → 计算与历史记录的相似度 → 按相似度排序 → 取 Top-k → 放入提示词 → LLM 参考这些示例推理
```

## 2. 什么是 Top-k

**Top-k** 指排序后相似度最高的前 k 条记录。

例如，当 `k = 3` 时：

1. 系统计算当前查询与每条历史记忆的相似度；
2. 按相似度从高到低排序；
3. 只保留前 3 条最相似的记录；
4. 这 3 条进入当前提示词，其余记录本轮不使用。

可以把记忆库想象成书架，Top-k 就是“只抽出最相关的几本笔记给模型看”。

## 3. 为什么进不了 Top-k 就很难攻击成功

恶意记录只有被检索进当前提示词，Agent 才可能模仿其中的错误推理。

如果恶意记录的查询与受害查询完全不像：

```text
查询不相似 → 相似度低 → 排名靠后 → 无法进入 Top-k
→ 恶意记录不会进入提示词
→ Agent 看不到恶意推理
→ Agent 无法模仿该记录
→ 攻击难以生效
```

因此，攻击记录的**输入**需要尽量接近受害查询，便于被检索；其**输出**才承载攻击者希望的错误推理。

## 4. 与 MINJA 的关系

MINJA 需要同时满足两件事：

1. **生成成功**：诱导 Agent 自己生成并保存恶意记录；
2. **检索成功**：后续受害查询到来时，该恶意记录能够进入 Top-k。

渐进缩短（progressive shortening）的目的之一，就是让最终恶意查询越来越像正常受害查询，从而提高被 Top-k 检索到的概率。

## 5. 最小例子

假设记忆库中有：

| 记录 | 历史查询 | 是否恶意 |
| --- | --- | --- |
| R1 | 查询患者 A 的处方 | 否 |
| R2 | 查询患者 A 的过敏史 | 否 |
| R3 | 查询患者 C 的体检报告 | 否 |
| R4 | 查询患者 A 的处方（但推理被导向患者 B） | 是 |

当前受害查询：

> 查询患者 A 的处方

若 `k = 2`，系统可能检索到 `R1` 和 `R4`。此时恶意记录进入提示词，Agent 才有机会模仿错误推理。

若恶意记录写成：

> 如何预订去火星的机票

则它与当前查询几乎不相似，通常无法进入 Top-k，攻击也就很难成功。

## 6. 一句话总结

> Top-k 决定“Agent 这一轮能看到哪些历史记录”；进不了 Top-k，就等于这条记忆对本轮推理几乎没有影响。
